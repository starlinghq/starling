# GLiNER2 entity extraction, CPU: uncontrolled development run, 2026-10-13

> **Uncontrolled development numbers, not G5 evidence.** One brief run on a shared workstation while other agents' builds, tests, soak runs and a GPU job ran (load average 10 to 22 on 12 logical CPUs, see the run table). The run shows that the harness works end to end and records what G5 needs; the timings are inflated and noisy and must not be compared with a budget or quoted as performance. The G5 budget for this profile is a maintainer decision (production-readiness plan, M2), and a G5 run needs a controlled machine (M6). Protocol: [PROTOCOL.md](PROTOCOL.md).

## Quality attached to the timings

Preliminary sweep: all 54 in-contract fixture cases (4 are outside the contract: more than 512 tokens, or the `max_len` word cap) extracted alone. 54/54 entity lists exact, confidence max abs 1.8e-6 against the protected bound 2e-5 (`float.confidence_max_abs`), logits finite. Every series passed its own check after its timed loop. The 100/250/400-word inputs have no upstream reference and were checked against the same text extracted alone at load (identical).

Cold start (fresh process, model in the OS page cache, n=5): spawn to first result 3,461 ms; session create 2,638 ms, tokenizer load 344 ms, first request 240 ms (prepare 55, inference 165, decode 20, JIT included).

What the run does show despite the noise: the ONNX Runtime run is more than 99% of every warm request; the C# preprocessing and decoding are below 4 ms even at 400 words. A batch of 8 short texts took about 5.6 times one text (no batching gain on this CPU at this size).
