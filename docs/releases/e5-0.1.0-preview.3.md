# e5 release candidate 0.1.0-preview.3

**Maturity: Preview** (plan 14). Same declared scope, API, platform statuses and qualification record as [0.1.0-preview.2](e5-0.1.0-preview.2.md). This candidate exists because the owned tokenizer's shipped bytes changed: `Starlings.Tokenizers` 0.1.0-preview.3 adds the Qwen byte-level BPE components (profiles `qwen2-bpe-kev` and `qwen35-bpe-chat`). The ai-dotnet packages pin the tokenizer version exactly, so they move to 0.1.0-preview.3 with it; their source is unchanged.

**Not published.** Nothing is on nuget.org and no tag exists; publishing is a maintainer action (`docs/kickoff.md`).

## What changed since 0.1.0-preview.2

| Package | Change |
| --- | --- |
| `Starlings.Tokenizers` 0.1.0-preview.3 | New components: NFC normalizer (Unicode 9.0.0 data, as the reference), `Split` with the two Qwen regexes, `ByteLevel` pre-tokenizer, post-processor and decoder, `BPE` model; profiles `qwen2-bpe-kev` and `qwen35-bpe-chat` packed under `profiles/`. Local changes L13 to L16 and new notices (unicode-normalization-alignments, MIT; Unicode License V3) in `tokenizers-dotnet/PROVENANCE.md` and `THIRD-PARTY-NOTICES.md`. Unigram path: one interface added to the model, no output change (every e5 and GLiNER2 tokenizer fixture passes). |
| `Starlings.Runtime.Onnx`, `Starlings.Acquisition`, `Starlings.Models.E5`, `Starlings.Models.E5.Extensions.AI`, `Starlings.Models.E5.MLNet`, `Starlings.Models.Gliner2` 0.1.0-preview.3 | Version only (and the exact tokenizer dependency `[0.1.0-preview.3]`). No source change. |

Manifests: `processing.tokenizer.version` is `0.1.0-preview.3` in `multilingual-e5-small/onnx-fp32-cpu`, `onnx-fp32-cuda` and `gliner2-base-v1/onnx-fp32-cpu`. Their gate evidence is unchanged: G1 and G2 were not rerun with the model for this candidate (decision for the maintainer: rerun them, or accept the tokenizer conformance suite as the G1 evidence for a tokenizer change that leaves the Unigram output unchanged).
