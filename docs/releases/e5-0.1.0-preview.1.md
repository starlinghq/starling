# e5 release candidate 0.1.0-preview.1 (P-010)

> Superseded by [0.1.0-preview.2](e5-0.1.0-preview.2.md) (faster tokenizer load, same behavior; G1, G2 and G6 rerun there). This page is the unchanged preview.1 record.

**Maturity: Preview** (plan 14). The declared scope below passes the phased gates, qualified by hand on 2026-10-09: G0, G1, G2 and G6 in full, G3, G4, G5 and G7 as short checklists (plan 10). The API and platform support may still change. Stable waits for qualification CI and controlled hardware profiles (P-018); every gate then applies in full.

**Not published.** Nothing is on nuget.org and no tag or GitHub release exists. Publishing waits for the `release` environment and the `Starlings` prefix reservation (`docs/kickoff.md`), and is a maintainer action.

## Known issues

- **Tokenizer cold start.** `E5Tokenizer.FromFile` takes about 1.3 s on the M0 workstation (the Rust tokenizer about 0.5 s), so a C# process reaches its first embedding about 1.7x later than Python. Optimizing the load in `Starlings.Tokenizers` was decided on 2026-10-09 and is in progress on a separate branch (`claude/tokenizer-fast-load`, possibly released as `Starlings.Tokenizers 0.1.0-preview.2`). This candidate pins `0.1.0-preview.1` exactly; adopting a new tokenizer version means a new ai-dotnet candidate (for example `0.1.0-preview.2`) with G1, G2 and G6 re-run (plan 14).
- **Double hashing at startup.** `E5ModelAssets.OpenLocal()` hashes both cached files by default (about 1.7 s for 487 MB on the M0 workstation) and the session hashes the model again when `ExpectedModelSha256` is set, as in the sample. Pass `new ModelAcquisitionOptions { Verification = CacheVerification.Size }` when the session checks the model digest.
- **Tokenizer quirks kept for fidelity.** The pinned `tokenizer.json` emits a lone `▁` before special-token literals and for trailing whitespace, and leaves decomposed Hangul jamo uncomposed, unlike SentencePiece (manifest `maintenance.known_issues`).
- **Package bytes are not reproducible.** Rebuilding the same commit gives different `.nupkg` bytes (random part names, timestamps). Publish the drilled files. There is no ai-dotnet candidate workflow that uploads them yet (the tokenizer has `release-tokenizers`).
- **Tokenizer package label.** `Starlings.Tokenizers` signals preview by its version suffix; its description does not start with "Preview." like the ai-dotnet packages (its project is outside this change).

## Reproduce

Linux x64 with the .NET 10 SDK, `unshare` (util-linux) for the offline step, Python 3.11 for the evaluator.

```sh
# G6 (and the packages-only G1/G2 checks): full download of both files (487 MB) ...
tools/release-drill-ai.sh
# ... or seed onnx/model.onnx from an existing snapshot (tokenizer.json is still downloaded)
tools/release-drill-ai.sh --seed-model-from /path/to/multilingual-e5-small-snapshot
# CI variant: no model
tools/release-drill-ai.sh --no-model

# G1: tokenizer release drill (tokenizer assets via tools/fetch-tokenizer-assets.sh into $STARLING_MODELS or .models)
tools/release-drill-tokenizers.sh

# G1/G2: staged fidelity evaluation (see model-pipeline/reference/README.md for the encoder environment)
python model-pipeline/reference/encoder/stage_e5_export.py --model-dir <snapshot> \
  --fixtures model-pipeline/protected/multilingual-e5-small/onnx-fp32-cpu \
  --profile multilingual-e5-small/onnx-fp32-cpu --out .models/e5-results
dotnet run --project ai-dotnet/tools/Starlings.Fidelity.Tool -c Release -- \
  e5 --snapshot <snapshot> --out .models/e5-results --hidden
model-pipeline evaluate model-pipeline/registry/multilingual-e5-small/onnx-fp32-cpu/manifest.yaml \
  --results .models/e5-results --out .models/e5-report --require-gates G1,G2

# G4/G7: repository tests with the model
STARLING_E5_SNAPSHOT=<snapshot> dotnet test --solution ai-dotnet/AI.slnx -c Release
```

Run for this page: 2026-10-09, Linux x64 (Intel i7-5820K, 12 threads), SDK 10.0.100 in the clone (global.json) and 10.0.401 for the consumers outside it, runtime 10.0.12. The workstation was shared with other work (load average 1 to 2 during the runs); none of these checks is timing-sensitive.
