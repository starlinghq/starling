# e5 release candidate 0.1.0-preview.2

**Maturity: Preview** (plan 14). Same declared scope, API and platform statuses as [0.1.0-preview.1](e5-0.1.0-preview.1.md); that page stays the full qualification record. This candidate exists because the owned tokenizer changed: `Starlings.Tokenizers` 0.1.0-preview.2 loads `tokenizer.json` about 4.8x faster with identical behavior, and the e5 manifests pin the tokenizer version exactly, so the four ai-dotnet packages move to 0.1.0-preview.2 with it. G1, G2 and G6 were rerun; the other gates carry over unchanged.

**Not published.** Nothing is on nuget.org and no tag exists; publishing is a maintainer action (`docs/kickoff.md`).

## What changed since 0.1.0-preview.1

| Package | Change |
| --- | --- |
| `Starlings.Tokenizers` 0.1.0-preview.2 | Load time only: `model.vocab` read from the bytes, pieces kept as UTF-8, double-array trie built from sorted keys without the DAWG pass, load loops compiled fully optimized at first call. Local changes L11 and L12 in `tokenizers-dotnet/PROVENANCE.md` (darts-clone `build_from_keyset` ported at `87b71afd6cf784953e3c08f24c64203397f3b724`, BSD 2-Clause, notice already packed). Description labeled Preview. No public API change, no output change. |
| `Starlings.Runtime.Onnx`, `Starlings.Acquisition`, `Starlings.Models.E5`, `Starlings.Models.E5.Extensions.AI` 0.1.0-preview.2 | Version only (and the exact tokenizer dependency `[0.1.0-preview.2]`). No source change. |

Manifests: `processing.tokenizer.version` is `0.1.0-preview.2` in `onnx-fp32-cpu` and `onnx-fp32-cuda`; the CPU manifest's G1, G2 and G6 evidence points here.

## Known issues

As in 0.1.0-preview.1, except the tokenizer cold start: `E5Tokenizer.FromFile` now takes about 0.24 to 0.27 s on the M0 workstation (was 1.3 s; the Rust tokenizer 0.50 s), and a C# process reaches its first e5 embedding in 944 ms against Python's 1,181 ms (was 2,047 ms, 1.73x Python). Measurements: [docs/benchmarks/tokenizer-load-2026-10-09.md](../benchmarks/tokenizer-load-2026-10-09.md).
