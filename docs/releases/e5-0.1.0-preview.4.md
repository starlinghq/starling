# e5 release candidate 0.1.0-preview.4

**Maturity: Preview** (plan 14). Same declared scope, API, platform statuses and qualification record as [0.1.0-preview.2](e5-0.1.0-preview.2.md). This candidate exists because the owned tokenizer's shipped bytes changed: `Starlings.Tokenizers` 0.1.0-preview.4 adds the Gemma BPE components (profile `gemma-bpe-embeddinggemma2`, for EmbeddingGemma 2). The ai-dotnet packages pin the tokenizer version exactly, so they move to 0.1.0-preview.4 with it; their source is unchanged.

**Not published.** Nothing is on nuget.org and no tag exists; publishing is a maintainer action (`docs/kickoff.md`).

## What changed since 0.1.0-preview.3

| Package | Change |
| --- | --- |
| `Starlings.Tokenizers` 0.1.0-preview.4 | New components: BPE byte fallback (`<0xNN>` per UTF-8 byte), unknown token with `fuse_unk`, `Split` with a `String` pattern (every behavior, `invert`), decoders `Sequence`, `Replace`, `ByteFallback`, `Fuse`; profile `gemma-bpe-embeddinggemma2` packed under `profiles/`. Local changes L17 and L18 in `tokenizers-dotnet/PROVENANCE.md`; notices unchanged in substance (same upstream, Apache-2.0). No public C# signature changed. Unigram and byte-level BPE paths: no output change (every e5, GLiNER2 and Qwen fixture and committed differential dump passes). |
| `Starlings.Runtime.Onnx`, `Starlings.Acquisition`, `Starlings.Models.E5`, `Starlings.Models.E5.Extensions.AI`, `Starlings.Models.E5.MLNet`, `Starlings.Models.Gliner2`, `Starlings.Generation.OnnxGenAI`, `Starlings.Models.Qwen35`, `Starlings.Models.Qwen35.Extensions.AI` 0.1.0-preview.4 | Version only (and the exact tokenizer dependency `[0.1.0-preview.4]`). No source change. |

Manifests: `processing.tokenizer.version` is `0.1.0-preview.4` in `multilingual-e5-small/onnx-fp32-cpu`, `onnx-fp32-cuda`, `gliner2-base-v1/onnx-fp32-cpu` and the three `qwen3.5-0.8b` manifests. Their gate evidence is unchanged: G1 and G2 were not rerun with the models for this candidate (decision for the maintainer, as for 0.1.0-preview.3: rerun them, or accept the tokenizer conformance suite as the G1 evidence for a tokenizer change that leaves the existing profiles' output unchanged).
