# Model catalog

Generated by `model-pipeline catalog` from the manifests in `model-pipeline/registry/`. Do not edit by hand: change the manifest and regenerate. CI fails when this file is stale (`model-pipeline catalog --check`).

Capability and platform statuses: `supported`, `unsupported`, `experimental`, `untested`, or `unrecorded` (the manifest records no status; never read as supported). Gate statuses: `passed`, `failed`, `checklist`, `not-run`, or `none` (the manifest records no entry for the gate).

Maturity and support are published separately (plan section 14). The compatibility matrix is [compatibility-matrix.md](compatibility-matrix.md); the same data, machine readable, is [catalog.json](catalog.json).

## Profiles

Gate cells link to the evidence the manifest records. The Stable readiness column applies the validator's Stable rules (every gate G0 to G7 `passed`, no capability `untested`) and lists exactly what fails them. Stable also needs regression support: CPU regression runs weekly on hosted runners, and GPU regression runs for every release (and on demand) on a RunPod GPU pod, so a CUDA profile is not promoted until that per-release GPU run is green for it.

## Known issues

- `embeddinggemma-2/image-fp32-cpu`: The image release set's reference stage tensors regenerate byte-identical only on the reference CPU at 6 threads; the accepted soft-token and token-embedding arrays are hosted at Starlinghq/starling-release-references (commit and file digests in the protected hosted-reference.json, #71), and the evaluator checks every array against the protected tensors.json, so the scheduled G2 needs no regeneration.
- `embeddinggemma-2/image-fp32-cpu`: One accepted release image (79 MP) exceeds the default 50,000,000-pixel limit; G1 and G2 pass with the limit raised for it (image_over_default_pixel_limit_with_option, experimental); the default stays a memory bound.
- `embeddinggemma-2/image-fp32-cpu`: Linux memory: Starlings.Runtime.Onnx calls malloc_trim on session release (on by default); the qualification soak runs with transparent huge pages `madvise`. No MALLOC_* setting is required on CPU; on `always` hosts resident memory can look larger without any leak.
- `embeddinggemma-2/image-fp32-cpu`: One CPU architecture (AVX2) produced the reference; PyTorch's generic uint8 kernel is expected to give the same resized bytes (same int16 weights), not verified. The C# resampler is integer arithmetic and machine-independent.
- `embeddinggemma-2/image-fp32-cpu`: The 16-bit fixture image (mode-gray16) has a reference row that no C# path reproduces: upstream renders it white, this profile rejects it.
- `embeddinggemma-2/image-fp32-cuda`: Contract hardware: an NVIDIA GeForce RTX 3090 (Ampere, sm_86), driver 580, CUDA 13 runtime. The CUDA gates G1 to G5 (G4 and G5 in the binding 2026-10-16 round) ran on RTX 3090s, and the per-release GPU regression is pinned to the RTX 3090 and refuses any other GPU (tools/ci/runpod.py).
