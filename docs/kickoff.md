## Repository settings to apply by hand

Agent sessions cannot change these: the GitHub connector has no settings API, and NuGet prefix reservation needs the account owner.

1. **Branch protection.** Settings > Rules > Rulesets > New branch ruleset. Target `main`. Enable: restrict deletions, block force pushes, require a pull request with 1 approval and review from Code Owners, require status checks `boundary`, `ai release-candidate drill`, `ai-dotnet`, `model-pipeline`, `repository checks`. While Mark is the only maintainer, add the repository admin role to the bypass list so PRs can still merge without a second reviewer.
2. **Release environment.** Settings > Environments > New environment `release`. Add Mark as required reviewer, restrict deployment branches to `main` and tags `v*`. Use NuGet trusted publishing (no stored key), as starlinghq/tokenizers does (`docs/releasing.md` there: the `NUGET_USER` variable is the policy creator's nuget.org user name). The tokenizer is released from its own repository; this repository's ai-dotnet release workflow is not written yet. Agent sessions do not add it.
3. **Fork PR policy.** Settings > Actions > General: keep "Require approval for first-time contributors", and keep the workflow token read-only.
4. **NuGet prefix.** Create the `Starling` organization on nuget.org, then request reservation of the `Starlings` ID prefix by email to account@nuget.org (see the NuGet ID prefix reservation docs). Reservation needs an owner account; it cannot be requested from here.

## Environment limits found during M0

The cloud environment's network policy blocks `huggingface.co` (and its CDN). Until it is allowed, agent sessions cannot download weights, `tokenizer.json` assets, or model cards, so reference runs and fixtures (P-003, P-004, P-027 spike) cannot run in a cloud session. GitHub clones, PyPI, and the NuGet v3 API work. A Hugging Face MCP connector was added on 2026-10-05: it reads repository listings and text files (configs, licenses, `tokenizer.json` sections, provenance files) but returns no commit SHAs, file digests, or binaries, so it supports verification but not downloads. To allow it: environment settings > Network access > Custom, add `huggingface.co` and `cdn-lfs.huggingface.co` (also `cas-bridge.xethub.hf.co` for Xet-stored files), keeping the default package managers.

Rechecked on 2026-10-05 at the start of the reference-runs session (branch `claude/m0-reference-runs`): `curl https://huggingface.co/api/models/intfloat/multilingual-e5-small` failed with `CONNECT tunnel failed, response 403`. The agent proxy reported `connect_rejected` (policy denial) for `huggingface.co:443` and `cdn-lfs.huggingface.co:443`; `cdn-lfs-us-1.hf.co` and `cas-bridge.xethub.hf.co` also failed to connect. Per the session instructions the work stopped at step 0 without any workaround: no Hub pins (`docs/m0/hub-pins.md`), no e5-small manifest or reference fixtures (P-002, P-003), no GLiNER2 tokenizer fixtures, and no Kev spike (P-027) were produced. All of them resume unchanged once the hosts above are allowed. Steps are at https://code.claude.com/docs/en/cloud-environments#network-access.

Resolved later on 2026-10-05: the hosts were allowed, downloads worked, and the reference-runs work above was completed in the same session (`docs/m0/hub-pins.md`, `docs/m0/reference-runs.md`).
