# Documentation

What each part of `docs/` holds. Start with the [root README](../README.md) for the packages and the quickstart.

| Path | Contents | Entry points |
| --- | --- | --- |
| [`plan/`](plan) | The execution plan and its workstream plans. | [fast-faithful-ai-dotnet.md](plan/fast-faithful-ai-dotnet.md) (goals, gates G0 to G7, maturity, bounded authority); [production-readiness.md](plan/production-readiness.md) (the path to Stable, maintainer actions M1 to M10); [maintained-update-drill.md](plan/maintained-update-drill.md); [embeddinggemma2-follow-up.md](plan/embeddinggemma2-follow-up.md); [model-onboarding-pipeline.md](plan/model-onboarding-pipeline.md); [five-model-onboarding.md](plan/five-model-onboarding.md) |
| [`catalog/`](catalog) | **Generated** by `model-pipeline catalog` from the registry manifests; CI fails when it is stale. Never edit by hand. | [README.md](catalog/README.md) (every profile, its maturity and the evidence for each gate); [compatibility-matrix.md](catalog/compatibility-matrix.md) (OS, architecture and provider per profile); [catalog.json](catalog/catalog.json) |
| [`guides/`](guides) | Guides for choosing and using models. | [choosing-an-embedding-model.md](guides/choosing-an-embedding-model.md); [native-runtimes-and-cuda.md](guides/native-runtimes-and-cuda.md) (native packages, the build-time check, CUDA builds, Native AOT) |
| [`benchmarks/`](benchmarks) | Dated benchmark reports (`<model>-<date>.md`, with `.summary.md`, `.summary.json` and raw `.jsonl` results), C# against Python on the same backend, and tokenizer measurements. Records of a run; not updated afterwards. | [PROTOCOL.md](benchmarks/PROTOCOL.md) (how G5 is measured); [e5-2026-10-09.summary.md](benchmarks/e5-2026-10-09.summary.md) |
| [`evidence/`](evidence) | Dated evidence records, one directory per gate run, qualification round, soak, diagnosis or promotion (for example `qualification-2026-10-16-cuda/`, `video-promotion-2026-10-17/`). The catalog links each gate to its record. Records are not rewritten. | [catalog/README.md](catalog/README.md) for the links per profile |
| [`releases/`](releases) | One record per release candidate or release (`ai-<version>.md`; earlier `e5-<version>.md`): packages, maturity, hosting, upgrade notes. Some have a directory of drill logs. | [ai-0.3.0.md](releases/ai-0.3.0.md) (current release) |
| [`m0/`](m0) | Milestone M0 spike and investigation reports (encoder selection, Hub pins, reference runs, tokenizer source audit, generation backend, GLiNER2, EmbeddingGemma 2 text/image/video, browser WebAssembly, landscape). Historical: later decisions are in `kickoff.md`. | [encoder-selection.md](m0/encoder-selection.md); [generation-backend-check.md](m0/generation-backend-check.md) |
| [`assets/`](assets) | README images (`demo.gif`, `social-preview.png`, `machine-view.svg`) and the scripts that render them (`render_assets.py`, `render_machine_view.py`). | |
| [`kickoff.md`](kickoff.md) | Open and settled project decisions, with where and when each was decided; repository settings applied by hand. | |
| [`support-policy.md`](support-policy.md) | What each maturity label commits the project to: support windows, regression support, security and correctness fixes, tokenizer bumps. Draft for maintainer review. | |

Release records, evidence and benchmark reports are dated records of what happened; a later change gets a new record, and an earlier release record stays as published (`support-policy.md`, promotion and demotion). Policy for contributions is in [`.github/CONTRIBUTING.md`](../.github/CONTRIBUTING.md).
