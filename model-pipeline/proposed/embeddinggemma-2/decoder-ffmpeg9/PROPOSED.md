# Proposed: the FFmpeg 9 decoder gate (`decoder_ffmpeg9`)

Status: **proposed** (R7 W4, 2026-10-13). Not protected evidence. Agents cannot write under `model-pipeline/protected/`; the maintainer commits the tolerance text below (follow-up plan section 1.1, "commit with W4, not before").

## What to commit

Append the contents of [`decoder_ffmpeg9.yaml`](decoder_ffmpeg9.yaml) (the text approved in `docs/plan/embeddinggemma2-follow-up.md` section 1.1, unchanged) to both:

- `model-pipeline/protected/embeddinggemma-2/video-fp32-cpu/tolerances.yaml`
- `model-pipeline/protected/embeddinggemma-2/video-fp32-cuda/tolerances.yaml`

The `decoder_ffmpeg` (FFmpeg 8) keys stay unchanged.

## What reads it

- The video evaluator (`model-pipeline/src/model_pipeline/evaluate_video.py`, this change): `decoder_ffmpeg9.*` is in `EXPECTED_KEYS` together with its check, `tokenizer.decoder_ffmpeg9_frame_sha256`. The check is added only when the protected tolerances carry the section, so the existing `video-fp32-cpu` G1 is unaffected until the file is committed. Once committed, G1 needs FFmpeg 9 decoder results in the same evaluation, and is not-run without them (a bound nobody checked never passes).
- One evaluation holds both decoder profiles: the tokenizer stage's own frames (`video<k>_frame_sha256`, major in `environment.ffmpeg_major`) and, per further adapter, `video<k>_frame_sha256_ffmpeg<major>` with an `environment.decoders` entry. `Starlings.Fidelity.Tool embeddinggemma2-videos --ffmpeg <FFmpeg 8 lib> --ffmpeg9 <FFmpeg 9 lib>` writes both from one run (both adapters load in one process; their library majors differ).
- The adapter tests (`ai-dotnet/tests/Starlings.Models.EmbeddingGemma2.Video.FFmpeg9.Tests`, the FFmpeg 8 tests compiled for FFmpeg 9) read `decoder_ffmpeg9.*` when present and otherwise hold the adapter to exact and say so.

## Reference

The bound is "exact against torchcodec on FFmpeg 9". torchcodec 0.17.0 on the machine's FFmpeg 9.0.1 (libavcodec 63.1.101) decodes every frame of the 22 fixture videos to the protected digests (torchcodec on FFmpeg 8.1): 5,367 of 5,367 frames, metadata and sampled indices equal ([`torchcodec-ffmpeg9.json`](torchcodec-ffmpeg9.json), from `model-pipeline/reference/embeddinggemma2/torchcodec_eg2_frames.py` with `EG2_TORCHCODEC_FFMPEG_MAJOR=9`, environment `requirements-video.txt`). So the gate compares with the protected `frame_sha256`; no new fixture file is needed.

| `model-pipeline evaluate` (`video-fp32-cpu`) on those stage 1 results, protected tolerances as committed | protected evidence verified; G1 passed, first divergence none; no FFmpeg 9 check added (`tokenizer.decoder_frame_sha256` passed, 32 video inputs) |
| The same results in a scratch clone with this proposal appended to the tolerances (never pushed) | `tokenizer.decoder_frame_sha256` passed (FFmpeg 8) and `tokenizer.decoder_ffmpeg9_frame_sha256` passed (FFmpeg 9), 32 video inputs each |

Stage 3 (embeddings) was not rerun for this change: the frames the embeddings use come from the FFmpeg 8 adapter, whose decoding is unchanged and still exact.

Not covered: an LGPL FFmpeg 9 build (none was installed; decoding does not depend on the license flags), other CPUs, FFmpeg 9 point releases other than 9.0.1.

## Bindings provenance

`ai-dotnet/src/Starlings.Models.EmbeddingGemma2.Video.FFmpeg9/FFmpegNative.g.cs` is generated by `tools/generate-ffmpeg-bindings.py --major 9` from the headers of FFmpeg n9.0.1, commit `bf1b838f2ab88b4f8fd83443325c782ea0e0f7fa` (installed from the source tree by `model-pipeline/reference/embeddinggemma2/fetch_eg2_ffmpeg9_headers.sh`). The same check (`--check`) passes against the distribution's headers. #41 regenerated the file from the distribution's 9.0.1 headers. On 2026-10-14 I regenerated it from the pinned commit's headers (a shallow fetch of `bf1b838f…` into a temporary directory, then `configure` and `make install-headers`), and the result is byte-identical to the committed file (SHA-256 `e31fd244df3e45997ff790f830cf0b8d67a1408f211531fe461b387ed899b424`). Every bound struct field has the same offset in FFmpeg 9.0.1 as in 8.1; only the library majors differ. Notices: `ai-dotnet/THIRD-PARTY-NOTICES.md`, `ai-dotnet/PROVENANCE.md`.
