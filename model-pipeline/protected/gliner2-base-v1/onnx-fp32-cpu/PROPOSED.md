Decisions for the reviewer:

1. Accept these as development fixtures for GLiNER2 entity extraction, with the PyTorch fp32 CPU public output as the reference (not the ONNX graph).
2. Entities compare on label, text, start, end and order. Most scores saturate to 1.0, so order under near-ties is backend-sensitive; decide whether near-ties within the score tolerance may swap (`docs/m0/gliner2-p014.md`, section 6 and decision 2).
3. Offsets are Unicode scalars of the normalized text (GLiNER2 appends `.`), so an entity can end one past the original text. Keep that as the contract or define a C# clamp.
4. The count gate never closed on this corpus; that path has no fixture.
