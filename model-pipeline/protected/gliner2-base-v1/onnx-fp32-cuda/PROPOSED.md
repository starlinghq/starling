# Accepted fixtures

Status: accepted as development fixtures by Mark on 2026-10-10 (PR #19); binding tolerances in `tolerances.yaml`. Parity results and environment only; there are no new goldens. The reference stays in `../onnx-fp32-cpu/extraction.jsonl` (PyTorch fp32 CPU), which the runner reads and does not modify.

Generated by `model-pipeline/reference/gliner2/parity_gliner2_ort.py --provider cuda --cuda-tf32 0,1 --batch-max-tokens 600` on one NVIDIA RTX 4060 Ti (driver 610.57.04, onnxruntime-gpu 1.30.0 with CUDA 13 and cuDNN 9.24 wheels), selected with `CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=1`. Another process held most of that GPU during the run, so the batch check leaves out the two cases over 600 tokens.

| File | Contents |
| --- | --- |
| `parity.json` | Route A (dynamo and TorchScript) and route B + H with `use_tf32=0` and `use_tf32=1`: hidden state, count logits, span logits, scores, entities, threshold flips, order-only differences, padded batches, repeatability. Per-case rows for route A dynamo with TF32 off. |
| `placement.json` | Per session: providers, provider options as ORT reports them, node counts per execution provider and the operators placed on CPU, from an ORT profile. |
| `environment.json` | GPU, driver, CUDA libraries, provider options, the reference read. |

Decisions for the reviewer:

1. The profile pins `use_tf32: 0`. With TF32 off, route A dynamo matches the reference on 58/58 cases (span logits max abs 4.0e-3, scores 2.5e-6). With ORT's default (TF32 on), span logits move by up to 2.4, one near-threshold span flips (`threshold-near-below-patient`) and one long case reorders entities.
2. ORT places 33 of 792 nodes of the dynamo graph on CPU (shape arithmetic) and adds one Memcpy. Accept that as the expected placement.
3. One GPU and one driver, shared with another job. Linux x64 CUDA stays experimental; Windows CUDA is untested.
