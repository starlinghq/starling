# Accepted fixtures

Status: accepted as development fixtures by Mark on 2026-10-11 (PR #47); binding tolerances in `tolerances.yaml` (CPU) and `../video-fp32-cuda/tolerances.yaml` (CUDA). Proposed by the EmbeddingGemma 2 video-path spike (`docs/m0/embeddinggemma2-video-spike.md`), 2026-10-11, for a video-embedding profile of `google/embeddinggemma-2` at `914f7f89142e33e77833254d9c9b90c3cef7303b`. The maintainer asked on 2026-10-11 to extend the contract to images, then video; the video contract itself is not decided yet (`model-pipeline/admissions/embeddinggemma-2.md`). No tolerances file: the proposed values are below and in the report (section 8), for the maintainer to set (plan 10.1).

Generated by `model-pipeline/reference/embeddinggemma2/run_embeddinggemma2_video.py` at repository commit `0af7a57` (clean tree; `video-environment.json`), CPU fp32 (torch 2.14.1, AVX2), torchcodec 0.17.0 on FFmpeg `n8.1.3-17-gc389840894` (BtbN LGPL shared build, `fetch_eg2_ffmpeg.sh`, archive SHA-256 checked), on the video set from `make_eg2_videos.py` (seed 20261011). An earlier run from a working copy of the same scripts produced identical embeddings and tensor digests. The videos (4.2 MB) and the tensors (732 MB of `.npz`) are not committed: `make_eg2_videos.py` regenerates the videos byte for byte with the pinned FFmpeg GPL build (checked by two generations), and the tensors are pinned by the SHA-256 digests in `tensors.json` and in each row.

Frame-sampling cases: `make_eg2_sampling_cases.py --out sampling-cases.json` (seeded; 20,849 cases, 5.3 MB, not committed) produced a file with SHA-256 `b9ef083bff2fb37aec9e2d66bd1d1bf9ea7e2f54b68ef64f20415361a362113a`; the C# port had 0 mismatches.

Proposed bounds (values only, report section 8): sampled indices, rendered ids, resized uint8 frames, pixel values and positions from decoded RGB exact (by digest); soft tokens and token embeddings within 1e-3 of the row's largest value; embedding max abs 1e-5 and min cosine 0.9999995; batched vs single 1e-5; no NaN/Inf; CUDA `use_tf32: 0` pinned. A decoder profile (FFmpeg adapter) would add: decoded RGB equal to torchcodec's on these videos (same FFmpeg major, x86-64).

Decisions for the reviewer:

1. Accept these as development fixtures for a video-embedding profile, or wait for the contract decision.
2. The reference is sentence-transformers fp32 CPU with torchcodec decoding on a pinned FFmpeg 8.1, as upstream runs it, including the quirks it pins: one frame for clips under 2 s, index-based sampling, all frames kept for an array without metadata (`vid-array-no-metadata`, a row a C# profile would reject rather than match), and FFmpeg's default 10-bit conversion.
3. Coverage limits: synthetic videos only (no camera footage); default settings only (1 fps, 32 frames, 140 tokens, no timestamps); no variable frame rate, interlaced or HDR; one CPU architecture (AVX2) for the reference and the decoder comparison.
