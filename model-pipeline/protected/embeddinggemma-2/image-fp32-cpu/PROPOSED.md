# Accepted fixtures

Status: accepted as development fixtures by Mark on 2026-10-11 (PR #42); binding tolerances in `tolerances.yaml` (CPU) and `../image-fp32-cuda/tolerances.yaml` (CUDA). Proposed by the EmbeddingGemma 2 image-path spike (`docs/m0/embeddinggemma2-image-spike.md`), 2026-10-11, for an image-embedding profile of `google/embeddinggemma-2` at `914f7f89142e33e77833254d9c9b90c3cef7303b`. The maintainer asked on 2026-10-11 to extend the contract to images; the image contract itself is not decided yet (`model-pipeline/admissions/embeddinggemma-2.md`). No tolerances file: the proposed values are below and in the report (section 8), for the maintainer to set (plan 10.1).

Generated by `model-pipeline/reference/embeddinggemma2/run_embeddinggemma2_image.py` at repository commit `f176f6f` (clean tree; `image-environment.json`), CPU fp32 (torch 2.14.1, AVX2), on the image set from `make_eg2_images.py` (seed 20261011, photos from scikit-image at commit `b700edc8005e4ee9e74fc83259f09e8df3213f15`). A second run from an earlier working copy of the same scripts produced byte-identical `image-embeddings.jsonl`, `image-preprocess.json` and tensor digests; `csharp-compare.json` and the C# runs used that earlier, identical output. The images and the tensors are not committed: `make_eg2_images.py` regenerates the images byte for byte (checked), and the tensors (631 MB of `.npz`) are pinned by the SHA-256 digests in `tensors.json` and in each row.

Proposed bounds (values only, report section 8): rendered ids, resized uint8 image, pixel values and positions from pre-decoded RGB exact (by digest); soft tokens and token embeddings within 1e-3 of the row's largest value; embedding max abs 1e-5 and min cosine 0.9999995; batched vs single 1e-5; no NaN/Inf; CUDA `use_tf32: 0` pinned. A decoder profile (SkiaSharp) would add: decoded RGB equal to PIL's on the supported images of this set.

Decisions for the reviewer:

1. Accept these as development fixtures for an image-embedding profile, or wait for the contract decision.
2. The reference is sentence-transformers fp32 CPU on PIL images (`Image.open`) with the torchvision image processor, as upstream runs it. Accept that, including the upstream quirks it pins: EXIF orientation ignored, alpha dropped, the 16-bit PNG rendered white (`mode-gray16`, a row a C# profile would reject rather than match).
3. Coverage limits: default vision budget (280) only; no video or audio; one CPU architecture (AVX2) for the reference.
