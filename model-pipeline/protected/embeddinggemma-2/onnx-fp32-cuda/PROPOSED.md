Status: accepted as development fixtures by Mark on 2026-10-10 (PR #29); binding tolerances in `tolerances.yaml`. Proposed by the EmbeddingGemma 2 admission spike. Parity results and environment only; there are no new goldens. The reference stays in `../onnx-fp32-cpu/embeddings.jsonl` (PyTorch fp32 CPU), which the runner reads and does not modify.

Generated by `model-pipeline/reference/embeddinggemma2/parity_embeddinggemma2_ort.py --provider cuda --cuda-tf32 0` at repository commit `f00f5d1e` on one NVIDIA RTX 4060 Ti (onnxruntime-gpu 1.30.0 with CUDA 13 and cuDNN 9.24 wheels; `environment.json`), selected with `CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=1`. Another process held about 10.7 GB of that GPU and kept it busy during the run; this affects timing only.

Decisions for the reviewer:

1. The profile pins `use_tf32: 0`. With ORT's default (TF32 on) the embedding moves by up to 1.9e-4 (min cosine 0.9999986) and padded batches differ from single rows by 3.1e-4 (`docs/m0/embeddinggemma2-spike.md` section 4); that run is not included here.
2. ORT places 130 shape-arithmetic nodes (`Concat`, `Slice`, `Squeeze`) on CPU. Accept that as the expected placement.
3. One GPU and one driver, shared with another job. Linux x64 CUDA would be experimental; Windows CUDA untested.
